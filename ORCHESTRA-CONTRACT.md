# Live orchestra contract

Keep the React/Vite/Express stack. This upgrade implements actual model-driven coordination/tool execution, not a scripted transcript or fixed template. Existing business APIs remain compatible. Single trusted local operator, no remote/multitenant claim.

## Shared runtime

Types: src/orchestra-types.ts. Roles: Coordinator, Website, CRM, Growth, Events, Billing, Review. Six department rooms plus Coordinator/CEO room.

Backend agent owns ONLY server/orchestra/** (engine.mjs, ollama.mjs, routes.mjs, prompts.mjs etc), server/orchestra.test.mjs. Export async registerOrchestraRoutes(app, {store, ollamaFetch=fetch, createTools}) from server/orchestra/routes.mjs. Main wires this AFTER existing business routes BEFORE express.static/error middleware. createTools(port) returns {catalog, execute, context}. catalog: [{name,description,agents:string[],parameters:JSONSchema}]. execute(name,args,{runId,taskId,agent,signal}) -> Promise<{status:'succeeded'|'awaiting_approval'|'blocked',message,recordId?,url?,approvalId?,data?}>; disallowed tool throws. context() -> JSON summary of business records (trusted IDs, untrusted user data). Main supplies fixed-loopback tool adapter using existing API validation and actual business actions. DO NOT access other files to edit. No browser/server spawn/model install in agent work.

Persist runs in store state.orchestraRuns initialized lazily to []. Store is serialized clone-based transactional update/get/id. Existing data must be retained. Store only public agent messages and action receipts, NOT model chain of thought. One inference/run at a time for 12GB GPU; queued runs are visible. AbortController cancellation + bounded inference, max 6 tasks and 5 specialist turns/task, no unlimited loops. On startup mark formerly planning/running queued states interrupted rather than silently rerun writes. Resume approval-waiting runs after real approval decisions (main API executes action); inspect approvals by ID via context and add verified outcome receipts, then continue. No duplicate create tools on resume. Explicit user resume endpoint, not silent retrigger. Resume interrupted work conservatively from saved receipts or reject with actionable message; no automatic retry of uncertain actions.

GET /api/orchestra -> {runs:AgentRun[],activeRunId:string|null}; POST /api/orchestra/runs {prompt,model} -> run with HTTP202; POST /api/orchestra/runs/:id/cancel -> run; POST /api/orchestra/runs/:id/resume -> run (409 if state inappropriate). GET polling is okay (UI 1.5sec only while active). Errors JSON {error}. Validate inputs. Model must be installed locally (status /api/tags, no automatic download). Backend context not exposed to remote model. Ollama fixed http://127.0.0.1:11434/api/chat; stream false, think false, structured schema, messages system+user; per-call120sec timeout includes body, num_ctx4096 num_predict1400, output bounded. Unsupported/unavailable model errors clear, no fake guided fallback.

Coordinator calls model to make task list {title,tasks:[{agent,instruction}]}. Each specialist gets its own system identity, user's goal, coordinator instruction, earlier public messages, actual receipts and business context. It calls model for {message,tool,args,done}; allowed tools schema/catalog supplied, args object. Execute model-selected allowlisted tool, persist receipt then feed it back on next model turn; done can finish a read/review task but cannot claim successful mutation without receipt. One final Review task may check records; no need artificial meetings. Public messages are real model response text and actual system/tool events. Errors/blockers do NOT appear as completed. Model output containing nonexistent IDs/tool names must fail safely. If sensitive tool returns approval wait, persist status awaiting_approval (and retain later tasks), don't treat pending as executed. Agents communicate via public messages/shared prior results, not fabricated thought streams.
